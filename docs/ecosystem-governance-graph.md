## Annex B — workflow-trigger conversion (operator-locked, 2026-10-09)

Operator decisions recorded for the trigger-conversion batch:

1. Keep `on: push: branches: [main]` (main-push exception); remove
   branch-push CI. This preserves the parity issues' main-push contract.
2. Convert CI workflows only; release/publish/deploy lanes keep current
   triggers.
3. PR checks and manual dispatch are gated fail-closed on the
   `state:implementation-go` label; `merge_group: checks_requested` always
   runs (it is the human-gated path).

Inventory: 94 of 144 first-party workflows carry a bare `push` trigger today
(Odyssey 16/29, Charybdis 11/11, Agamemnon 10/11, Odysseus 8/13; Athena 0/4 —
the reference shape). Four smoke-only `merge_group` carrier workflows remain
(Myrmidons, Odysseus, Odyssey, Telemachy) and #386 requires their absence.

## Annex C — assumptions corrected by the audit

Earlier session notes asserted the Odysseus live main ruleset already carried
the 180-minute HEADGREEN merge-queue rule. The live read shows Odysseus has
**no** `merge_queue` rule at repository level (F1): the payload is tracked
(`configs/github/repo-ruleset.json`) but never applied. Mnemosyne needed no
cut-over issue because it is already fully conformant, making 15 (not 14)
cut-over nodes. Odysseus #492 blocks Athena #164 only, per its own body — it
is not a fleet-wide cut-over blocker. No organization rulesets exist, so no
`admin:org` token scope is required for this program.
